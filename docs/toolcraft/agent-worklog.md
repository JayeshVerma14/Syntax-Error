# Toolcraft App Agent Worklog

## Status

Mode: product

Active change: syntax-error-006

Syntax Error builds halftone and glyph-film branding assets: a source is sampled onto a grid and every cell is redrawn as a repeated unit — a disc, square, star, seal, bar, or any typed glyph set on a monospace character grid — coloured from an editable brand ink list, then optionally surrounded by an idle field, bursts, swirls and typed captions, posed in perspective, glitched, and animated as a seamless loop.

## Decision Trail

### syntax-error-001 — Initial product delivery

- Request: Build a branding-asset tool inspired by an inspected halftone image maker, "not very exactly same but mostly same and inspired also putting some great thoughts and effort to add more features", whose stated gap was "adding other symbol/character/svg icon as unit like other shape". Follow-up answers selected PNG and MP4 delivery, four source kinds, and four additions: dither engines, a column layout, a multi-glyph tone ramp, and brand palettes.
- Task type: New Toolcraft product — schema, custom Canvas 2D renderer, playback timeline, media upload, image and video export.
- User-visible result: A controls panel with Source, Grid, Unit, Tone, Response, Palette and Motion sections driving a live halftone sheet, plus runtime Image Export and Video Export with Export PNG and Export MP4 actions.
- Source/reference checked: The user supplied reference material for an existing halftone tool plus four still outputs. That material was reviewed through a headless browser to read its control panel: Pixel Size, Canvas Height, the Tools/Patterns/Color/Image/Video tabs, Shape Mode (Random, Circles, Squares, Octagons, Small Circles + Squares), palette type and 1/2/3-colour modes, image contrast and lightness, and PNG/SVG export. That review is design rationale only; it is not registered framework reference evidence, for the reason recorded under Reference inputs.
- Reference inputs: None registered; the list is empty. The protected preprocessing command cannot run in this environment: one stage calls ffmpeg `drawtext` without `fontfile=`, and fontconfig in the installed Windows ffmpeg 9.0.2 build faults (0xC0000005) with and without a supplied `FONTCONFIG_FILE`; another builds a `select` expression of up to 120 `eq(n\,N)` terms, while ffmpeg's expression parser accepts at most 100 and returns ENOMEM beyond that, measured by bisection. Both stages live in files covered by the signed integrity manifest, so neither can be patched. No artifacts were fabricated and no `reference-parity` rows were declared.
- Docs/contracts read: `AGENTS.md`; `docs/toolcraft/workflow.md`; core modules `reference-study.md`, `runtime-boundary.md`, `control-selection.md`, `layout.md`, `setup-export.md`, `media-upload.md`, `timeline-animation.md`, `performance.md`; plus `assembly-workflow.md`, `schema-reference.md` and `component-rules.md`.
- Contract rules applied: `runtime-shell-required` — the product is assembled through `defineToolcraft`/`composeToolcraftApp` and the signed route is untouched. `canvas-no-app-ui` — `scene.canvasContent` holds one product-output canvas and no chrome; the empty-source canvas stays neutral with no placeholder artwork. `controls-product-coverage` — every visible control declares `applicability` and a `performanceRole`. `output-export-required` — image export is the runtime default and video export carries explicit request evidence. `timeline-mode-choice` — playback timeline, required because MP4 export was requested.
- View interaction intent: `non-spatial`. The output is a flat sheet; there is no three-dimensional scene or model, so no orientation gizmo and no camera authority are declared.
- Interaction ownership: Empty. Every operation is a panel property edit. There is no canvas drag, selection, or handle, so no operation could plausibly live on either surface and nothing is mirrored.
- Decision: One sampled ink field feeds every stage, so the four source kinds stay interchangeable. `engine-source` rasterizes image, SVG, footage frame, or wordmark into a cols-by-rows grid; `engine-tone` shapes it and applies the selected dither; `engine-units` draws the mark; `engine-palette` picks its ink. Preview and both artifacts call the same `renderSyntaxErrorFrame`, so the canvas is what a PNG or MP4 frame contains. Glyph units are ordinary members of the shape vocabulary rather than a separate mode, and the glyph list is a `collectionActions` collection so users own its cardinality.
- Alternatives rejected: A separate "ASCII mode" beside the shape selector — rejected because it would split one decision, the mark drawn per cell, across two controls. A WebGL renderer — rejected because the workload is a few thousand fills per frame, which Canvas 2D handles inside the interactive budget without a GPU pipeline. Sampling the source once at full resolution and downsampling per cell — rejected because sampling straight to grid resolution is the same result for less work. A `palette` control for inks — rejected because brand inks are free hex values, not constrained design tokens, so `collectionActions` with a `color` item is the exact owner.
- State/output mapping: `grid.cell` sets grid resolution and is the one workload dimension. `grid.mode`, `grid.gap` and `grid.jitter` place each unit. `unit.shape` selects the draw routine, and gates `unit.glyphs` and `unit.ramp` through applicability. `unit.scale` and `unit.floor` map ink to unit size; `unit.angle` rotates it. The `tone` targets shape the field before any unit is drawn, and `tone.dither` gates `tone.cutoff`. `palette.mode` gates `palette.inks` and the shuffle command. `motion.style` gates `motion.amount` and `motion.stagger`, and drives a forward-only loop read from timeline progress. `export.includeBackground` and `appearance.background` are the authored Background pair runtime relocates into Setup.
- Performance intent: ordinary-product-work
- Verification: `npx tsc -p tsconfig.json --noEmit` passes. The app was driven live in a browser at 1080 by 1080: the wordmark source renders a two-ink dot halftone, the Glyph unit renders the same wordmark as a hash-weighted ASCII field, and the glyph collection, tone ramp switch and shape selector appear and disappear with their applicability branches. First-delivery proof is owned by the protected `npm run verify:delivery` receipt.
- Risks: Risk: Footage sources seek one decode per evaluated frame, so export latency scales with decode speed on long clips; cadence is unaffected because runtime owns the 30 FPS schedule. Risk: The protected preprocessing could not run in this environment, so the app carries no `reference-parity` coverage and fidelity rests on the design review recorded above. Risk: Very small cell pitches on a large artboard approach the declared interactive boundary; the grid is capped at 1024 cells per axis to keep that bounded.

### syntax-error-003 — Mark mixing and colour matching

- Request: "I want features like the reference, multiple shapes all thogeter option / I f I want to add some characters along with square, then I should be able to / colors are not properly implemented, like there is not a proper way to mix them, colors should be properly mixed", with three reference stills attached.
- Task type: Feature correction — the unit vocabulary becomes composable, and ink assignment gains real colour matching.
- User-visible result: Shape gains a Mix choice that reveals an editable Marks set plus a Spread selector, so a square, a circle and a glyph can be drawn together on one sheet. Palette gains a Match selector (Tone, Nearest, Blend) and a Diffuse switch.
- Source/reference checked: The three attached stills were read directly. Two are outputs of the reference tool: a panther on orange, and a portrait rendered in black, orange, pink, yellow-green, green and pale blue. In both, colour follows the source hue rather than its brightness — hair stays black while skin goes warm and the backdrop keeps its own hue, which a brightness ramp cannot produce. The third still is the reference panel, confirming its Shape Mode is single-select.
- Reference inputs: None registered; the list stays empty for the reasons recorded in syntax-error-001.
- Docs/contracts read: `core/control-selection.md` for collection cardinality and the exact owner of a growable set, and `component-rules.md` for segmented budgets and collection item controls.
- Contract rules applied: `controls-product-coverage` — the four added controls declare applicability and a performance role, and Match is classified as a branch because Diffuse depends on it. `canvas-no-app-ui` — the change is renderer-side only; no new canvas chrome.
- View interaction intent: `non-spatial`, unchanged.
- Interaction ownership: Unchanged. Both additions are panel property edits with no spatial component.
- Decision: The previous build assigned ink by luminance alone, which is why a five-ink palette still produced brightness bands rather than the reference's separated hues. Colour matching is now its own pass that maps each cell's actual RGB to the palette: `nearest` picks the closest ink under a green-weighted distance, `blend` weights the two closest, and an optional Floyd-Steinberg diffusion in colour space carries the matching error into neighbouring cells so two inks mix into a gradient. `tone` is kept as the previous behaviour rather than removed. For shapes, the single-select Shape control keeps every individual mark and gains `Mix`, which reveals a `collectionActions` set of marks plus a Spread selector; repeating an entry weights it. Glyph settings now apply to both the single Glyph mark and a Mix containing it.
- Alternatives rejected: Replacing the Shape select outright with a multi-select set — rejected because picking one mark is the common case and would have become a two-step interaction, and because applicability predicates cannot test membership of an array, which would have stranded the glyph controls. Matching in a perceptual space such as CIELAB — rejected for now because a green-weighted RGB distance is close enough at palette sizes of a handful of inks and avoids a conversion per cell per frame. Diffusing on by default — rejected because hard-edged matching is the look in the attached panther still.
- State/output mapping: `unit.shape` gains `mix` and gates `unit.mix` and `unit.mixOrder`; the glyph list and ramp now gate on `oneOf ["glyph", "mix"]`. `palette.match` selects the colour assignment and gates `palette.diffuse`. Both feed `unit-build` and `unit-draw` in the renderer pipeline.
- Performance intent: ordinary-product-work
- Verification: `npx tsc -p tsconfig.json --noEmit` passes and the static acceptance, coverage and performance validators pass. Driven live in a browser against one of the attached stills: under Tone the five-ink palette produced brightness bands, and switching to Nearest reproduced the reference's separated hues — green backdrop, black hair, warm face. Setting Shape to Mix with Circle and Glyph drew both marks across the same sheet.
- Risks: Risk: Colour matching runs over every cell each time the ink list, match mode or diffusion changes, so a very small cell pitch on a large artboard makes that pass the dominant cost. Risk: Diffusion is sequential by construction, so it cannot be split across workers without changing its result. Risk: The green-weighted RGB distance is an approximation; a palette of near-identical hues may match in an order a perceptual space would not choose.

### syntax-error-005 — Motion styles, keyframes and decode-once sampling

- Request: "add some more motion styles, more creative ones and add keyframe option to the timeline"
- Task type: Feature addition — a motion engine with sixteen looping styles, and the timeline moved from playback to keyframes, which required restructuring source sampling.
- User-visible result: Motion Style offers Pulse, Heartbeat, Wave, Ripple, Sweep, Scan, Rain, Twinkle, Drift, Orbit, Spin, Vortex, Morph, Decode, Reveal and Shake besides Still, with Amount, Cycles, Direction and Stagger. The timeline is now a keyframe timeline: every slider, colour and curve shows an Add keyframe button, and an added keyframe opens its own row with easing in the expanded timeline panel.
- Source/reference checked: No new material was supplied. The styles are agent-designed for the glyph-field look recorded in syntax-error-004, and the existing sheet was the only visual checked.
- Reference inputs: None registered; the list stays empty for the reasons recorded in syntax-error-001.
- Docs/contracts read: `core/timeline-animation.md` for keyframe mode, keyframe capability by control type and which passes playback may invalidate; `core/performance.md` for renderer pipeline pass declarations.
- Contract rules applied: `timeline-mode-choice` — keyframes mode on an explicit request. Keyframe capability — every keyframe-capable control stays keyframeable, with none opted out. Timeline invalidation — playback and scrub invalidate only `unit-build` and `unit-draw`, never `source-sample`.
- View interaction intent: `fixed-camera`, unchanged. Camera properties are keyframeable like any other slider, so a camera move is authored as ordinary keyframes.
- Interaction ownership: Unchanged.
- Decision: Every style is a function of wrapped time `t = progress × cycles` with a whole number of cycles, so each returns exactly to its first frame at the loop point. Styles act on four channels — offset, scale, rotation, and a shift through the glyph ramp or Mix marks — so they compose with every unit shape. Keyframes forced a structural change: the validators require keyframe-capable controls to stay keyframeable, which puts Cell size on the playback path, and resampling per cell size would have decoded the source on every played frame. The source now decodes once per source change into summed-area tables at the finest cell pitch, and the grid for any cell size is box-averaged from them in constant time per cell. Keyframed Cycles values round to whole repeats. Running the product source boundary afterwards surfaced violations carried from earlier deliveries, and all but one were corrected: the painting canvas now carries its canvas-handle marker, sampling buffers are detached `OffscreenCanvas` surfaces, still images are polled for load rather than wired to load handlers, and two call sites whose argument types exhausted the boundary's bounded analysis now pass narrow values. The oversized schema and acceptance modules were split into `src/app/schema/` and `src/app/acceptance-data/`. The same pass fixed two source bugs: the Typeface picker's font never reached the wordmark, which always fell back to a system face, and a paused clip parked on its first frame never drew.
- Alternatives rejected: Keeping playback mode — rejected because the user asked for keyframes. Opting Cell size, Cycles and the brush and pattern values out of keyframing — rejected because the framework forbids opting out capable controls, and it would have withheld keyframes from exactly the values users animate most. Resampling the source whenever cell size changes — rejected because a keyframed cell size would then decode the source every frame. Free-running random motion — rejected because it cannot close a loop and an MP4 would not match the preview.
- State/output mapping: `motion.style` gates `motion.amount`, `motion.cycles` and `motion.stagger`, and `motion.direction` applies only to the directional styles. `grid.cell` now feeds `unit-build` instead of `source-sample`, which depends only on source targets. Timeline playback and scrub invalidate `unit-build` and `unit-draw`. Keyframes on `tool.color`, `tool.size`, `pattern.scale` and `pattern.angle` change what the next stroke or fill writes at the playhead rather than animating existing output.
- Performance intent: ordinary-product-work
- Verification: `npx tsc -p tsconfig.json --noEmit` passes, and `engine-motion.test.ts` and `engine-camera.test.ts` pass, 39 of 39, including loop closure for every style. `vitest run src` ends 747 passed and 3 failed; the failures are two protected tests whose fixed 5 and 20 second limits this machine exceeds (one builds a TypeScript program of the whole project, about 80 seconds here) and one Windows path-separator assertion, and none exercises product code. In a browser, the expanded timeline shows Add keyframe buttons on 26 product controls, and adding a Cell size keyframe opens its row at 0.00s. Rendering every style to pixels at 2 cycles confirmed each returns to its first frame at the loop point and moves mid-loop. Deriving the grid from the decoded raster measured about 1 ms at 45 by 45 cells and 4 ms at 270 by 270, against about 15 ms for one decode. Keyframed playback itself was not observed live, because the browser pane was hidden and ran no animation frames. After the boundary corrections, `scripts/check-toolcraft-integrity.mjs` and `scripts/check-toolcraft-code-health.mjs` report only `src/app/engine/engine-footage.ts`; image, footage and wordmark sources render in the browser, and a wordmark set in Playfair Display rasterizes differently from Inter once the face loads.
- Risks: Risk: `src/app/engine/engine-footage.ts` still fails the product source boundary, because it creates a video element and listens for its seek events; this Toolcraft version offers product code no other frame-accurate video decode path, and its codec library is reserved for export. `npm test`, `ai:check` and focused feature verification stop on that module until footage moves to a DOM-free decoder or the Video source is removed. Risk: Footage still decodes one frame per played frame by nature; the decode-once guarantee covers image, SVG and wordmark sources. Risk: Brush and pattern keyframes change what the next stroke or fill writes; they do not animate cells already painted. Risk: At cell pitches that are not a whole multiple of the 2px sampling step, neighbouring cells average one or two samples, which can add faint banding at the finest settings. Risk: Keyframed playback was verified through the pipeline contract and pixel renders rather than watched live in this session.

- Decision: The glyph look was wrong at its root. Glyphs were sized by tone on a square grid, so the sheet read as a halftone of letters rather than a character film. In the film every character is one size on a monospace grid, and tone only picks which character. The Type layout sets cells at a 0.6 width-to-height ratio, and fixed sizing draws one bold size per cell. The ramp gains an empty step below its first character so the darkest cells stay bare, and each cell shifts up to one ramp step by noise so flat areas mix neighbouring characters. Knockout boxes a share of bright cells in runs of three: it fills the cell and cuts the character out, which is the boxed-letter effect. Field, Burst and Swirl are passes over the same grid. ## Decisions

### Renderer

- Decision: Canvas 2D, one deterministic frame function shared by preview and both artifacts.
- Reason: The output is some thousands of filled paths and glyph runs per frame with no per-pixel shading, which Canvas 2D draws inside the interactive budget; a GPU pipeline would add a provider and export surface for no fidelity gain.
- Evidence: `src/app/engine/engine-render.ts` holds the shared renderer; `src/app/engine/product-canvas.tsx` draws the preview and `src/app/engine/engine-export.ts` supplies `scene.rasterFrameRenderer`. `rendererStrategy: "canvas-2d"` in `src/app/app-performance.ts`.

### View Interaction

- Decision: `fixed-camera`.
- Reason: The sheet can be posed in perspective, which makes the view spatial. The user asked for camera angle properties, so the pose is authored as panel properties and keyframes, and the canvas takes no pointer input.
- Evidence: `appProductReadiness.viewInteraction` in `src/app/app-acceptance-data.ts` carries `explicit-user-request` authority quoting "there are some camera angle properties too"; the projection and its inverse live in `src/app/engine/engine-camera.ts`; no `orientationGizmo` control exists in `src/app/app-schema.ts`.

### Interaction Ownership

- Decision: None. Every operation is a panel property edit.
- Reason: Canvas painting was the only canvas-owned operation, and the user removed it: "remove brush and paint, it's unnecessary". Nothing that remains is spatial.
- Evidence: `appProductReadiness.interactionOwnership` is empty in `src/app/app-acceptance-data.ts`; `src/app/engine/product-canvas.tsx` has no pointer handlers, and `src/app/app-schema.ts` no longer composes `canvasEditingModule()`.

### Timeline

- Decision: Keyframe timeline, four-second default loop.
- Reason: MP4 delivery requires the top timeline, and the user then asked for a keyframe option on it. Motion styles loop inside the timeline duration on their own; keyframes layer authored changes on top, and every keyframe-capable control can carry them.
- Evidence: `timelineModule({ defaultDurationSeconds: LOOP_SECONDS, mode: "keyframes" })` in `src/app/app-schema.ts`; `animationIntent.mode: "timeline-keyframes"` and the `timelineCoverage: "keyframes"` rows under `src/app/acceptance-data/`; the wrapped-time maths in `src/app/engine/engine-motion.ts`, whose tests assert every style returns to its first frame; playback and scrub invalidate only `unit-build` and `unit-draw` in `src/app/engine/engine-pipeline.ts`.

### Layers

- Decision: Not enabled.
- Reason: No layer workflow was requested. The product takes one source at a time and composes a single sheet. The field, burst, swirl and caption are fixed passes of that sheet, each with its own section, rather than user-ordered layers.
- Evidence: No `layersModule()` in `src/app/app-schema.ts`; `appSchema.panels.layers` is asserted undefined in `src/app/app-schema.test.ts`.

### Controls

- Decision: Fourteen product sections — Source, Guides, Grid, Unit, Field, Tone, Response, Palette, Burst, Swirl, Caption, Camera, Glitch, Motion — grouped by the entity each edits, with Tone split into two workflow stages sharing one `entityId`. Each section leads with the control that defines or gates it — Cell size, Shape, Idle field, Color, Burst effect, Swirl effect, Caption text, View, Glitch effect, Style — followed by its parameters, then its one-shot commands. Unit places its Terminal look command directly under Shape because it rewrites the whole unit look.
- Reason: Section boundaries follow user task and reset scope. The response curve is an atomic compound editor with its own graph surface, so it is its own stage rather than the sixth field under the numeric tone controls. Runtime keeps authored control order, so the gate has to be authored first for its dependants to appear beneath it. A control gated by a selector must sit in that selector's section, which is why the glyph typesetting controls live in Unit rather than a section of their own.
- Evidence: Section definitions live in `src/app/schema/` and are composed in order by `src/app/app-schema.ts`. `appControlSectionInventory` in `src/app/acceptance-data/section-inventory.ts` declares each `entityId`, `targets`, `groupingReason` and `finiteSelectors`, including the shared `tone` entity with `workflowStage` and `splitReason`.

### Export

- Decision: PNG image export at runtime defaults plus MP4 video export. No SVG.
- Reason: Image export is on by default; video carries explicit user-request evidence. SVG was offered in the same exchange and not selected, so it stays `not-requested`.
- Evidence: `appProductReadiness.exportIntent` in `src/app/app-acceptance-data.ts` records the verbatim quote "png and mp4" with its transcript locator; `imageExportModule()` and `videoExportModule()` in `src/app/app-schema.ts`; no `svgExportModule()`.

### Performance

- Decision: One inverse workload dimension, `grid-cell-pitch`, bounded at the schema minimum, plus the runtime-owned `export-output-pixels`.
- Reason: Cell pitch is the only control that changes how many units are drawn, and smaller pitch is heavier, so its maximum workload is its minimum value. Every other control, including the camera, glitch and motion controls, transforms the same unit count. The field and burst draw only into cells of the same grid, and the swirl is capped at 600 particles, so neither adds a workload dimension. Cell pitch no longer triggers a decode: the grid is box-averaged from a raster decoded once per source change.
- Evidence: `workloadEnvelope` and `fixtureAdapters` in `src/app/app-performance.ts`; `performanceRole: "workload"` appears once in the schema, on `grid.cell` in `src/app/schema/schema-sections-sampling.ts`.
